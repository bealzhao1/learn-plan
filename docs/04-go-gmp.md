# GMP 调度模型

## 4.1 核心概念

```
┌─────────────────────────────────────────┐
│              Go Runtime                  │
│                                          │
│   G (Goroutine)    M (Machine/Thread)    │
│   ┌───┐ ┌───┐     ┌───┐ ┌───┐          │
│   │ G │ │ G │     │ M │ │ M │          │
│   └───┘ └───┘     └───┘ └───┘          │
│                                          │
│   P (Processor)                          │
│   ┌───┐ ┌───┐                           │
│   │ P │ │ P │   (GOMAXPROCS 个)         │
│   └───┘ └───┘                           │
└─────────────────────────────────────────┘
```

| 组件 | 含义 | 说明 |
|------|------|------|
| **G** | Goroutine | 轻量协程，初始栈 2KB，可动态增长 |
| **M** | Machine | 操作系统线程，实际执行代码 |
| **P** | Processor | 逻辑处理器，持有本地运行队列（LRQ） |

## 4.2 调度流程

```
          全局队列 (GRQ)
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
┌──────┐  ┌──────┐  ┌──────┐
│  P0  │  │  P1  │  │  P2  │   (本地队列 LRQ, 最多256个G)
│[G G G]│  │[G G] │  │[G G G]│
└──┬───┘  └──┬───┘  └──┬───┘
   │         │         │
   ▼         ▼         ▼
┌──────┐  ┌──────┐  ┌──────┐
│  M0  │  │  M1  │  │  M2  │   (OS 线程)
└──────┘  └──────┘  └──────┘
```

## 4.3 调度策略

1. **Work Stealing（工作窃取）**：P 的本地队列为空时，从其他 P 偷一半 G
2. **Hand Off（移交）**：M 阻塞时，将 P 移交给空闲 M 或新建 M
3. **抢占式调度**：
   - Go 1.14+ 基于信号的异步抢占（`SIGURG`）
   - 解决了 `for {}` 死循环无法被调度的问题
4. **Spinning Thread**：至少一个自旋 M 在轮询，减少唤醒延迟

## 4.4 调度时机

- channel 阻塞 / 解除阻塞
- `go` 关键字创建新 goroutine
- 系统调用（syscall）阻塞
- GC STW / 辅助标记
- `runtime.Gosched()` 主动让出
- 函数调用时的栈增长检查点（协作式抢占）
